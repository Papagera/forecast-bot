GDELT DOC 2.0 `enddatetime` нестрогий: на запрос с концом 2026-06-01 00:00 все 50 статей пришли из 06-01 18:15 … 06-02 00:00 (проба 05.10.2026). При `sort=datedesc` верх выдачи целиком из «лишних» суток.

**Why:** бэктест Polymarket 3A — любая статья после t = утечка будущего. Строгий фильтр без сдвига окна оставлял бы пусто.

**How to apply:** серверу отдавать конец окна на 24 ч раньше t (`gdelt.SERVER_LEAK`), отсечку `seendate < t` делать на клиенте всегда. Заодно: в `ai_guard` сутки считаются по МЕСТНОМУ времени (`_day_start`), а этапы и окна — в UTC; потолок этапа с началом в UTC не видел трат, сделанных до полуночи UTC. GDELT после серии отказов держит 429 часами — качать в кэш заранее, не во время прогона.
