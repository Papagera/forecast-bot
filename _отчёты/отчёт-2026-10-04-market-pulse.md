# Market Pulse · подготовка бота · 04.10.2026

Источник фактов о турнире — API `projects/tournaments/market-pulse-26q3/` (описание и поля), 04.10.2026.

## Правила и очки
- **Регистрации/кнопки Join нет.** `default_permission: forecaster`, у бот-аккаунта `user_permission: forecaster`,
  `has_participated: false` — участие начинается с первого прогноза. `bot_leaderboard_status: include`.
- 🔴 **«you can only enter the competition once, either as a bot or as a normal user»** — если бот входит,
  Никите нельзя участвовать своим человеческим аккаунтом.
- **Очки — `spot_peer_tournament`:** «only your predictions standing at the close time of each question matter»;
  итог — сумма spot-очков по вопросам. Усреднения по времени НЕТ.
- 26Q3: 12 групп, 65 подвопросов, $7 500, 214 участников; старт 08.07, приём прогнозов до 16.09, закрытие 06.10.
- **Ритм подвопросов:** период «Jul 27 – Aug 7» открывается ≈ за неделю до начала периода и закрывается в момент
  его начала (пример: открыт 03.08 16:00, закрыт 10.08 03:00 UTC) → на момент spot-оценки весь период в будущем.
- Тексты условий закрытых вопросов API не отдаёт (по документации — только тем, кто в них прогнозировал), поэтому
  определения рядов ниже — допущения по названию группы; в подсказке прогнозисту они названы допущениями.

## Что сделано (PR)
- **Группы:** forecasting-tools 0.3.2 сам разворачивает `group_of_questions` в подвопросы
  (`get_all_open_questions_from_tournament`, `unpack_subquestions` по умолчанию); прогноз уходит на id подвопроса,
  комментарий — на пост группы. Проверено тестом на групповом посте.
- **Турниры из переменной репо** `FORECAST_TOURNAMENTS` (по умолчанию `fall,minibench`). Включить Market Pulse:
  `gh variable set FORECAST_TOURNAMENTS -b "fall,minibench,pulse" -R Papagera/forecast-bot` — без деплоя.
  `pulse` → слаги прошлого/текущего/следующего квартала (`market-pulse-26q3/26q4/27q1`), пересчитываются на каждом
  опросе цикла; несуществующий сезон тихо пропускается → 26Q4 начнёт прогнозироваться сам, как только появится.
  Любой другой слаг — через запятую в той же переменной.
- **Обновления при spot-очках:** для Market Pulse «не дважды» не действует; прогноз освежается раз в сутки и раз
  в 3 ч в последние 12 ч до закрытия (`needs_update`). Для Fall/MiniBench «не дважды» остаётся.
- **Quant по рядам** (`quant.pulse_quant`, флаг `--quant-hints`, в workflow включён): распределение исхода по
  историческим окнам той же длины, данные строго до сегодняшней даты:
  UST 10Y — FRED `DGS10`, HY OAS — FRED `BAMLH0A0HYM2` (аддитивные изменения); max VIX — Yahoo `^VIX` High;
  относительные доходности NVDA/MSFT/AAPL и фьючерсов NQ/ES/GC/CL — Yahoo (`NQ=F`, `ES=F`, `GC=F`, `CL=F`).
  🔴 Stooq с 10.2026 закрыт JS-проверкой браузера — не используется (и инструмент агента `stock_history` в бою
  сейчас пуст — заменить на Yahoo отдельной правкой).
- **Для подвопросов по рядам поиск не запускается** — прогнозист получает только базу quant: подвопрос обновляется
  до ~11 раз, поиск на каждое обновление дал бы ≈1 430 вызовов AskNews за квартал (≈оценка) при потолке 900/мес.
  Подвопросы по отчётности (выручка, EPS, guidance) — с обычным исследованием (агент, ≤2 поиска).

## Частота и деньги
Подвопрос открыт ≈7 дней → ≈7 суточных + ≈4 финальных обновления ≈ 11 прогнозов. Сухой прогон: $0.023 за прогноз
(Opus 5.5 high без поиска). 65 подвопросов × 11 × ≈$0.03 ≈ **$21 за квартал ≈ $0.25/сутки** (≈оценка;
по отчётности с агентом дороже, ≈$0.05) — внутри $6/сутки с большим запасом.
