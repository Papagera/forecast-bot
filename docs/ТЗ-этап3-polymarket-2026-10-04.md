1. **Только чтение.** Публичные API без ключа: Gamma (`gamma-api.polymarket.com/markets`) и CLOB

   **Ни строки кода, способной торговать** — держит гард (см. «Гарды»), а не обещание.
2. **Деньги на ИИ:** все вызовы — через ai_guard, отдельное приложение `polymarket`, **$2/сутки**;
   на весь этап **≤ $20** — второй потолок по леджеру от даты старта этапа (отказ = честный стоп).
3. **Публичный репо:** решения Никиты, его вероятности, журнал виртуальных сделок и chat_id — **вне репозитория**:
   `~/.forecast-bot/polymarket/` (SQLite). В git — только код, тесты и агрегированные отчёты без решений по рынкам.

## Проверено по первоисточникам (04.10.2026)
- `GET clob.polymarket.com/prices-history?market=<token_id>&interval=max&fidelity=<мин>` — без авторизации, ответ
  `history: [{t, p}]` (docs.polymarket.com/developers/CLOB/timeseries); на закрытом рынке живьём — 232 дневные точки.
- Gamma `markets`: у закрытых рынков есть `startDate`, `closedTime`, `outcomes`, `outcomePrices` (итог 1/0),
  `umaResolutionStatus`, `clobTokenIds`, `volumeNum`, `liquidityNum`, `feeType`, `negRisk`, `spread` (живой запрос).
- Комиссии (docs.polymarket.com/polymarket-learn/trading/fees): maker 0; taker `fee = C × feeRate × p × (1 − p)`,
  feeRate по категориям: Geopolitical 0, Finance/Politics/Tech 0.04, Sports/Economics/Culture/Weather/Other 0.05,
  Crypto 0.07. Ввод/вывод USDC — без комиссии Polymarket.

## A. Бэктест «только бот»
**Выборка.** Закрытые бинарные рынки (Yes/No), итог однозначен (`umaResolutionStatus = resolved`, цена исхода 1/0),
срок жизни `closedTime − startDate` ≤ 30 дней. Сегменты по объёму `volumeNum`:
- **хвост** (основная гипотеза): малые объём и ликвидность — нижние квантили (рабочая граница ≈ $10k объёма,
  уточняется по распределению выборки);
- **контроль**: ликвидные рынки (≥ $250k объёма);
- отдельно отмечаются `negRisk` (ноги многоисходных событий) и категория по `feeType`.
Цель — ≈ 250 рынков, из них ≥ 150 хвостовых.

**Дата прогноза.** Для каждого рынка — точка `t0 = startDate + 50% срока жизни`, но не позже чем за 24 ч до
`closedTime`. Цена рынка — последняя точка `prices-history` до `t0`. Боту — текст рынка и описание, «сегодня» = `t0`,
**без поиска** (свежие новости = утечка будущего, архив AskNews — 5 вызовов на запрос). Цену рынка бот НЕ видит —
нужна независимая оценка.

**Утечка.** Opus 5.5: reliable knowledge / training data cutoff — июнь 2026 (platform.claude.com, Models overview).
Рынки с `t0` ≤ 30.06.2026 — отдельная строка «до cutoff», в выводы не идут. Основной результат — `t0` ≥ июля 2026.

**Модель.** Прогнозист — Opus 5.5 high (как в бою), без исследования; ≈ $0.02–0.03 за рынок по сухому прогону
Market Pulse (≈оценка) → 250 рынков ≈ $6–8, при потолке $2/сутки — 3–4 дня прогона.

**Метрики (по сегментам и для «до/после cutoff»):**
- log score и Brier: бот vs рыночная цена в `t0` vs смесь (среднее в логитах);
- виртуальная прибыль: вход, если `|p_бот − цена| ≥ порог` (сетка 0.05 / 0.10 / 0.15); покупка недооценённой
  стороны по цене + половина спреда (исторического стакана API не даёт: хвост — 3¢, контроль — 1¢, ≈оценка,
  чувствительность по спреду показывается) + taker fee по `feeType`; держим до резолва; ставка — 1 доля;
- число сделок, доля прибыльных, ROI на вложенное, доверительный интервал (бутстрэп).

**Итог A** — таблица «сегмент × порог: сделок, ROI после издержек, Brier бот/рынок» и вывод: есть ли
преимущество и где. Приёмка A — у income; без «да» B не запускается.

## B. Бумажная торговля с модерацией, 3–4 недели (после приёмки A)
- **Раз в день 3–5 кандидатов** в Telegram из открытых рынков сегмента, где A показал преимущество:
  рынок, ссылка, цена, p бота, расхождение, 3–5 строк «почему» с источниками (исследование — агент варианта B со
  сверкой чисел `[S#]`), срок резолва.
- Кнопки **✅ / ❌**; по желанию — своя вероятность ответом на сообщение.
- **Три виртуальных портфеля:** всё предложенное ботом / только ✅ / только ❌; вход по цене момента отправки +
  половина текущего спреда + taker fee; 1 доля на сделку.
- **Ежедневная сводка** позиций; после резолва — итог по каждой сделке и по портфелям.
- **Telegram:** бот `@claude_bestwife_bot`, токен `POLY_TG_BOT_TOKEN` в `.env` (не печатать, не коммитить).
  Свой слушатель `getUpdates` — копия логики из `clipper/publish` (копия, не импорт; у клиппера свой токен —
  два слушателя одного токена конфликтуют). **Привязка чата по одноразовому коду:** бот публичен по username,
  поэтому `/start` принимается только с кодом, который печатается локально; дальше — только этот chat_id.
- **Где крутится:** локально на маке (журнал решений вне репо) — слушатель и суточная рассылка. Нужен
  LaunchAgent или ручной запуск — **решение Никиты** (см. «Вопросы»).

## Критерий «продолжаем»
Портфель **✅ в плюсе после издержек на ≥ 50 закрытых сделках** И **лучше портфеля «всё подряд»**. Иначе — стоп,
отчёт и закрытие этапа.

## Гарды (каждый — тест + мутация в `tools/mutate_guards.py`)
- **Нет торгового кода:** тест сканирует репозиторий и падает на `py_clob_client`, `private_key`, `eth_account`,
  подписи EIP-712, POST на `/order` / `/orders` CLOB, любых не-GET запросах к доменам Polymarket.
- **Только GET:** HTTP-клиент модуля `polymarket` разрешает лишь GET на белый список хостов.
- **Деньги:** приложение `polymarket` в `APP_LIMITS` ($2/сутки) + потолок этапа $20 по леджеру; неизвестное
  приложение запрещено (уже есть).
- **Данные вне репо:** путь базы — `~/.forecast-bot/polymarket/`, тест на то, что он вне `paths.main_checkout()`.
- **Утечка в бэктесте:** цена и данные строго до `t0` — тест на фейковой истории.
- **Telegram:** чужой chat_id игнорируется; `/start` без кода не привязывает.
